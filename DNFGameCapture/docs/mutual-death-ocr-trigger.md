# 同归于尽 OCR 触发修复

## 原因
左右大 X 共用普通击杀 10 秒冷却。第一侧触发后，第二侧新死亡边沿只能等冷却结束且 X 仍存在才补触发，可能已经错过当前对打双方的画面。计分层现有规则并不禁止完整的 A→B 与 B→A 两条记录，因此不应通过取消 60 秒重复死亡去重解决。

## 本次调整
- 保留大 X 连续两帧稳定判定。
- 普通自动识别开始时建立 1500 ms 同归于尽窗口；物理左右不受界面翻转影响。
- 仅在另一物理侧产生新的稳定死亡边沿、双方 X 同时存在时，立即派发另一侧 OCR。每个窗口只允许对侧一次。
- 首侧 X 消失、检测重置、超过窗口后，不走此快捷通道；维持原有普通/局间冷却逻辑。
- 若第一侧已启动局间冷却，已确认这一对死亡的另一侧仍可在短窗口内识别，但不得重设/缩短局间计时器。
- 不更改重复死亡、同一击杀方向重复计分、死者遮挡时杀手重复识别等去重规则。
- 冷却拦截日志显示具体原因，便于区别检测防抖与最终落账去重。

## 回归
策略单测：`scripts/mutual_death_trigger_policy_test.cpp`，可用 C++17 编译，无 Windows 依赖。覆盖同帧双侧、左右顺序、单侧重复、双侧稳定性、窗口边界、10 秒延迟、首侧复位、检测重置、非法侧和 32 位 tick 回绕。

实机验收仍需同归于尽录像：应出现 `[同归于尽]` 日志，两条识别分别处理相反的物理死亡侧。双方均成功识别后各增加一击杀和一死亡；保持 X 不消失不应再计分。另需检查最后一人的同归于尽与大比分结算。

本次不改队伍大比分平局规则、不根据一个 X 推断双死、不直接复制第一条 OCR 的姓名；双方仍需经过原有识别与去重。1500 ms 是新引入的保守默认阈值，需要用实际录像验证。

早期策略验证产物位于 `build/mutual-death-check/`。该修复现已合入 5.5.0，随最新 EXE 部署至解决方案根目录 `x64/Release/`；后续同步高度调整与完整发布说明见 `release-5.5.0.md`。
