## 修复与调整

### 同归于尽 OCR 触发

- 第一侧正常触发后建立 1500 ms 配对窗口；另一侧出现新的稳定死亡边沿且双方 X 同时存在时，允许立即派发对侧 OCR，避免被共享的普通冷却延迟。
- 配对窗口只放行对侧一次；首侧 X 消失、检测重置或超时后失效。
- 保留两帧稳定判定、重复死亡/击杀去重和局间冷却；对侧补触发不重设或缩短局间计时器。
- 冷却拦截日志补充具体冲突原因。详见 `mutual-death-ocr-trigger.md`。

### 实时同步窗口高度

- 由原生 `m_cloudRealtimeFollowing` 状态驱动窗口扩高。
- 同步时增加 64 CSS 像素，当前 1.25 倍视觉基准下约为 80 屏幕像素，为顶部红色只读提示留出空间；停止同步后恢复。
- 扩高叠加于各面板尺寸计算之后，打开/关闭面板不会丢失提示空间；重复状态广播不会反复调整窗口。
- 保留显示器工作区边界限制，不修改窗口宽度与 Web 缩放。

### 主播列表高度适配

- 桌面宽度下，实时同步期间取消主播侧栏原有最大高度限制，使用 size containment 与 flex stretch，使其与左侧底部对齐。
- 新增空间分配给内部可滚动主播列表，长列表不反向撑高外层窗口。
- 停止同步后恢复原高度；窄屏规则及其他主题保留。
- 不重新设计主播卡片、状态文案或同步操作入口；两份独立设计预览不纳入仓库和交付。

## 构建与交付

正式交付统一放到解决方案根目录的 `x64/Release/`：

```text
x64/Release/
  DNFGameCapture.exe
  WebView2Loader.dll
  web前端/
```

不是内层 `DNFGameCapture/x64/`。本次最新构建输出在工程目录 `build/release-5.5.0-realtime-height/bin/`，EXE 保留 5.5.0；最后的侧栏调整只更新前端，无需重编 EXE。

当前已部署 EXE SHA256：`2EBD394F8AC2BE80B3B457CB03F23E69142F4024546F7134FE347F98C15FA4C8`。

升级时先关闭程序并备份，再更新配套 EXE、DLL 和前端；前端更新后重启生效。保留原有授权、个人配置、选手库和 OCR 环境，不迁移或清空数据。仍需要 WebView2 Runtime、VC++ x64 运行库及原有 OCR 环境。

此前的 `5.5.0-original-ui` 目录及压缩包是较早阶段产物，不包含全部后续高度修复，不能作为本次最新发布包使用。
