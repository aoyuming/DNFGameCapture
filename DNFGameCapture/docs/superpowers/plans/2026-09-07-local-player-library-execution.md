# 本地选手库实施记录

## 实施范围

本次执行规范化本地选手库方案。数据库、共享 ID、后台 Store、身份管理、冒险团 ID 编辑和云端 v2 编码已接入客户端。未修改云函数、比赛服务器或比赛快照字段。

## 根据现有代码调整

- 本地游戏 ID 保留 `DnfAliasSameStorageEntry` 的大小写和职业比较规则，不采用原计划示例中的 NFC/ASCII 大小写折叠，避免丢失原本不同的 ID。
- SQLite 使用仓库现有依赖中的 3.49.2 源码，固定源文件 SHA-256，静态编译；不另引入旧版 3.46.1。
- 云端编解码与快照投影分别放在 Database/Model 中，没有额外创建只转发函数的 CloudCodec 文件。
- 主线程使用 Timer 10 每 100ms 排空完成队列，不让后台线程向可能已销毁的窗口投递裸指针。
- 确认后的编辑命令串行提交，不合并不同的归并/解除命令。保存期间保留前端草稿并阻止重复提交；普通比分变化不再上传整份本地库。未实现原计划中的 200ms 写入合并窗口。
- 当前事务重写名称和关联表，并重建后台不可变快照，尚未实现逐行增量 SQL 更新。高频读取使用缓存和索引，不重新计算整个库。
- 测试授权模式数据库单独保存到 `%APPDATA%\DNFGameCapture\test\player_library.db`；常规模式保存到其上级目录。
- 迁移临时数据库使用 DELETE journal，关闭后安装，再切换 WAL；不移动正在使用的 WAL 数据库。
- 当前保留兼容 INI 导出，不提供直接编辑旧 INI 后自动回读的入口。

## 已核对结果

- 核心数据库测试：通过迁移、共享 ID、事务失败、只读回退、归并/拆分、云端导入和压力用例。
- Release 库副本：122 个名称，1094 次 ID 引用，452 个唯一 ID，数据库保存 452 个 ID；最终迁移和索引对照 37ms。
- 用户提供的旧公共库副本：122 个名称，985 次 ID 引用，468 个唯一 ID，数据库保存 468 个 ID；最终迁移和索引对照 38ms。
- 两份原始 INI 的 SHA-256 均未变化。所有审计写入均在临时副本中进行。
- 12,200 个名称压力样本：建立和保存约 602ms，100,000 次索引查询约 18ms。这是本机测试值，不是跨设备性能保证。
- 身份算法测试：10,000 个名称的完全一致/热门 ID/稀疏集合样本均通过，稀疏样本分析约 21ms。
- OCR 缓存测试通过：场上八人、临时移除 ID、游戏 ID 优先、唯一冒险团归属、新鲜证据和击杀后保护。
- 服务端回归：11 个测试文件、116 项测试全部通过。
- 前端行为测试：20 项通过，包括版本过滤、只读状态、编辑草稿、冒险团编辑、分组排序、仅冒险团选手选择、编辑器宽度和统一缓存版本。
- 浏览器假数据验证：1280 宽建议区只显示两行，其余可滚动；900x600 身份编辑器无横向溢出；无 JavaScript error 日志。假数据页面不连接实际云端。

## 审查修复

- 新导入的名称写入身份组成员表；完整或部分解除归并均保留全部名称及原实体关联。
- 专业窗口名称和游戏 ID 使用显式重命名事务，成功后才更新场上数据。只在显式游戏 ID 重命名时保留对应战绩，不从集合差异猜测重命名。
- 临时移除的游戏 ID 不会因尚未完成的重命名再次出现。对局配置和专业树列表在成功提交及回调后同步保存、刷新。
- 云端来源取自请求时捕获的地址。每个来源的已接收 revision 在事务内保存；较旧版本拒绝，相同内容不增加本地 revision。
- 云端 ID 与已有归属冲突时整次导入失败，不部分修改。旧 INI 迁移产生的多个尚无云端 ID 的本地实体允许首次合并拉取，但不被强制归为一个实体。
- 异常身份元数据验证后忽略；有效旧 INI 仍可迁移或只读回退。
- Unicode 校验改为按需加载 System32 中的 ICU；无系统 ICU 时使用保守校验。核心程序已通过无硬 ICU 导入检查，不需随包安装 ICU。
- 上述 8 项核心回归用例全部通过；最终核心压力样本为 563ms，100,000 次查询为 18ms。
