# 记分板字体样式设置设计

## 背景

当前 Web 计分窗口上方的红队/蓝队记分板已经包含队名、比分、表头、选人顺序、主号名和战绩数字等多类文字。用户希望只针对上方红蓝记分板增加字体设置能力，并且只按文字类型统一设置，不再区分红队和蓝队；每类文字可以设置字体、字号、颜色、描边颜色、描边宽度和发光效果，同时避免底部按钮继续膨胀。

本设计只覆盖红队/蓝队记分板区域，不影响底部控制区、弹窗、随机工具、OBS TXT 输出格式和核心识别逻辑。

## 目标

- 增加一个低打扰的“外观”入口，用于打开记分板样式设置。
- 按文字类型统一调整样式，红队和蓝队同时生效。
- 每组样式支持字体、字号、颜色、描边颜色、描边宽度和发光强度。
- 设置后 Web 端实时预览，关闭重开程序后仍能恢复。
- 提供恢复当前类型默认和恢复全部默认能力，减少现场调参成本。

## 非目标

- 不做每个选手行、每个选手名字的独立样式。
- 不做红队和蓝队的独立样式配置。
- 不修改底部控制区文字样式。
- 不修改 `击杀.txt`、`左侧人头.txt`、`右侧人头.txt` 的输出规则。
- 不引入新的 OBS 浏览器源或额外窗口。
- 不复制字体文件，只保存系统字体 family 名称。

## 样式对象

按文字类型分成 6 组样式：

- 队名。
- 比分。
- 表头。
- 选人顺序。
- 主号名。
- 战绩数字。

同一文字类型同时作用于红队和蓝队。“战绩数字”同时作用于击杀、死亡和 AK 输入框；表头作用于“击杀 / 死亡 / AK”文字；选人顺序作用于“先选 / 后选 / 1选...”标签。

## 可编辑属性

每组样式包含：

- 字体：从系统已安装字体中选择，默认回退到 `Microsoft YaHei`。
- 字号：建议范围 10px 到 48px。
- 颜色：文本填充色。队名和比分默认使用“跟随队伍色”，即红队沿用红色、蓝队沿用青色；用户切换到自定义颜色后，红蓝两侧同一文字类型使用同一个颜色。
- 描边颜色：用于文字描边。
- 描边宽度：0px 到 4px，0 表示关闭描边。
- 发光强度：0px 到 24px，0 表示关闭发光。

Web 端用 CSS 变量承载这些值，实际文字描边优先使用 `-webkit-text-stroke`；发光使用 `text-shadow`。为了兼容没有描边需求的默认状态，默认描边宽度为 0。

## UI 设计

底部控制区新增一个 `外观` 按钮，位置放在 `专业模式` 附近。按钮进入外观弹窗。

外观弹窗采用左右结构：

- 左侧为样式对象列表：队名、比分、表头、选人顺序、主号名、战绩数字。
- 右侧为当前对象的编辑器。
- 底部提供 `恢复当前默认`、`恢复全部默认`、`关闭`。

编辑器使用紧凑控件：

- 字体下拉框。
- 字号数字输入或滑杆。
- 颜色输入框。
- 描边颜色输入框。
- 描边宽度数字输入或滑杆。
- 发光强度数字输入或滑杆。

弹窗打开时直接预览当前样式；修改任何字段立刻应用到上方记分板。恢复当前默认和恢复全部默认只恢复本功能的样式配置，不重置比分、选手和战绩。

## 数据结构

C++ 内部保存一个 `scoreboardTextStyles` 状态，按 key 管理：

```json
{
  "teamName": { "fontFamily": "Microsoft YaHei", "fontSize": 22, "colorMode": "team", "color": "#ffffff", "strokeColor": "#000000", "strokeWidth": 0, "glow": 8 },
  "score": { "colorMode": "team" },
  "header": {},
  "pickLabel": {},
  "playerName": {},
  "statNumber": {}
}
```

缺失字段使用默认值补齐，方便兼容旧配置。`colorMode` 只支持 `team` 和 `custom`；除队名和比分外，其它类型默认使用 `custom`。

## 持久化

样式配置保存到现有 `config.ini` 的独立段落，减少新增文件带来的发布和迁移问题。

示例 key：

```ini
[ScoreboardTextStyles]
teamName.fontFamily=Microsoft YaHei
teamName.fontSize=22
teamName.colorMode=team
teamName.color=#ffffff
teamName.strokeColor=#000000
teamName.strokeWidth=0
teamName.glow=8
```

程序启动时读取配置并广播给 Web。Web 修改后发送 `cmd_set_scoreboard_text_styles`，一次提交完整样式配置，C++ 保存并广播最新状态。

## 系统字体

C++ 枚举系统已安装字体 family 名称，并在 `BroadcastStateToWeb()` 中同步给 Web。Web 字体下拉框使用该列表。若配置中的字体不存在，Web 和 C++ 均回退到 `Microsoft YaHei`。

## 默认样式

默认样式应尽量保持当前视觉：

- 红队队名和比分保留红色发光。
- 蓝队队名和比分保留青色发光。
- 表头保留灰白色。
- 选人顺序保留金色。
- 主号名和战绩数字保留白色。
- 默认描边宽度为 0。

## 数据流

1. Web 页面启动发送 `page_ready`。
2. C++ 广播当前记分板状态、样式配置和系统字体列表。
3. Web 把样式配置转换为 CSS 变量并应用到红蓝记分板根节点。
4. 用户打开“外观”弹窗并调整字段。
5. Web 立即更新 CSS 变量进行预览，同时把完整样式配置发给 C++。
6. C++ 清洗并保存配置，然后广播最新状态，保证多次打开 Web 状态一致。

## 校验和容错

- 字号、描边宽度和发光强度限制在允许范围内。
- `colorMode` 非法时回退到该文字类型的默认颜色模式。
- 颜色只接受 `#rgb` 或 `#rrggbb`，非法值回退默认。
- 字体名称去掉换行、引号和过长文本。
- 如果 Web 收到旧版状态中没有样式配置，使用默认样式。
- 如果系统字体列表为空，字体下拉框至少提供 `Microsoft YaHei`、`SimHei`、`Arial`。

## 测试计划

- 默认打开后，上方记分板视觉与当前版本基本一致。
- 修改主号名字号、颜色、描边后，红队和蓝队主号名同时变化。
- 修改战绩数字字体和发光后，红队和蓝队击杀、死亡、AK 数字同时变化。
- 修改选人顺序样式后，红蓝两侧“先选 / 后选 / 1选...”标签同时变化，规则本身不变。
- 队名和比分默认跟随队伍色；切换为自定义颜色后，红蓝两侧对应文字变为同一个颜色。
- 使用“恢复当前默认”后，当前文字类型回到默认视觉。
- 使用“恢复全部默认”后，所有文字样式回到默认视觉。
- 关闭并重开程序后，样式配置保持。
- 旧配置文件无样式字段时不报错并使用默认值。
- Web 静态检查、Release x64 构建通过。

## 开放点

第一版暂不做样式预设导入导出。若后续现场需要多套皮肤，可以在本设计基础上增加“保存为预设 / 载入预设”。
