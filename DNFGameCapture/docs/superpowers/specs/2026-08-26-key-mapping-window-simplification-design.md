# 按键映射窗口简化设计

## 目标

将当前按键映射功能从“框选技能栏并 OCR 读取 16 个键位”简化为固定 `2x7` 键位映射。用户只需要使用默认键位或逐格手动绑定，直播伴侣通过独立透明窗口捕获响应效果，不再要求配置网页地址。

## 默认键位

按行保存和展示 14 个技能格：

- 第一行：`Q W E R T Y Ctrl`
- 第二行：`A S D F G H Alt`

首次使用或配置项不存在时采用以上默认值。用户手动清空或修改的键位继续持久化；设置面板提供“恢复默认键位”命令，用于显式恢复全部 14 格。

## 主界面设置

“更多 > 工具 > 按键映射”保留以下功能：

- 启用或关闭按键响应。
- 打开或关闭按键映射展示窗口。
- `2x7` 键位网格，点击某格后按一个键盘单键完成绑定。
- 清除当前键位。
- 每格独立设置高亮颜色和透明度，并可应用到全部。
- 一键恢复默认键位。

删除以下功能和界面：

- 框选技能栏。
- OCR 读取键位和候选确认。
- 复制 OBS 网址。
- 技能栏区域状态、源分辨率和重新校准提示。

## C++ 状态与持久化

全局映射固定为 14 格。`[KeyMappingSlots]` 继续保存每格的虚拟键、显示名称、颜色和透明度，兼容用户已经保存的前 14 格样式和键位。未保存过的格子使用新默认值；旧配置中的第 15、16 格不再读取或展示。

删除按键映射区域、区域失效、框选鼠标状态、OCR 线程、OCR 回调和相关 Web 命令。保留 `GetAsyncKeyState` 轮询规则：默认 DNF 目标仅在游戏位于前台时响应，其他捕获目标仅在监控运行时响应。

## 展示窗口

保留独立窗口 `DNF Key Display - DNF按键映射窗口`，行为与 KILL 展示窗口一致：

- 无边框透明窗口。
- 可移动、可缩放、不置顶。
- 悬浮时显示移动、缩放和关闭控件。
- 关闭后只隐藏窗口，不退出主程序。
- 记住窗口显隐、位置和尺寸。
- 页面固定 `2x7`，未按键时完全透明，按下时显示对应格子的半透明颜色层。

内部继续使用 WebView2 渲染透明内容，但主界面不再提供或复制网页地址。对用户和直播伴侣只暴露可捕获的命名窗口。

## 数据流

1. C++ 每 16 毫秒读取 14 个虚拟键的按下状态，生成 `activeMask`。
2. 本地展示状态提供 `2` 行、`7` 列和 14 个格子的颜色、透明度。
3. 展示窗口中的 WebView2 每约 33 毫秒刷新状态，只绘制当前按下的格子。
4. Web 主界面修改键位或样式后发送设置命令，C++ 保存配置并立即更新展示状态。

## 错误处理

- 无效或鼠标虚拟键统一拒绝并保存为空。
- 重复绑定允许存在，相同键对应的多个格子同时高亮。
- 展示服务不可用时禁用“打开响应窗口”，并保留明确提示。
- 功能关闭、目标窗口不满足响应条件或展示窗口隐藏时，不影响主监控和比赛数据。

## 验证

- 首次打开显示 `QWERTY + Ctrl` 和 `ASDFGH + Alt`。
- 14 格均能手动绑定、清除并持久化。
- “恢复默认键位”恢复固定两行配置，不改变颜色和透明度。
- 框选、OCR、OBS 网址相关按钮、命令、状态和线程全部移除。
- 展示窗口可被直播伴侣按标题找到，可移动、缩放、关闭和恢复。
- 多键、长按、松开、重复绑定的高亮状态正确。
- Release x64 构建、前端语法、静态检查和真实窗口状态接口验证通过。
