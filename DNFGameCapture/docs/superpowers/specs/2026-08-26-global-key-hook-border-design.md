# 按键映射全局响应与窗口边框设计

## 背景

当前按键映射每 `16ms` 通过 `GetAsyncKeyState` 轮询，并且会按“默认 DNF 必须在前台”或“其它捕获源必须正在监控”限制响应。旧版配置还可能明确保存 14 个 `Vk=0`，导致窗口始终没有高亮。

本次将按键响应改为 Windows 全局低级键盘钩子，并给 KEY 套壳窗口增加可见的矩形边框。

## 交互与视觉

- 勾选“启用按键响应”后，无论 DNF、主 Web、C++ 窗口或 KEY 窗口哪个位于前台，物理键盘按下都会高亮对应格子。
- 按住期间持续高亮，松开立即恢复透明。重复绑定同一键时，对应的多个格子同时高亮。
- KEY 套壳窗口显示一圈常驻半透明青色矩形边框，鼠标悬浮时提高亮度。边框不填充内部，不影响技能画面叠加。
- 边框仅在 `keys.html?shell=1` 套壳窗口中显示，不改变普通页面渲染。

## 输入架构

- C++ 使用 `SetWindowsHookEx(WH_KEYBOARD_LL, ...)` 安装全局低级键盘钩子。
- 功能启用时安装钩子；功能关闭、窗口销毁或程序退出时调用 `UnhookWindowsHookEx`。
- 钩子回调只处理 `WM_KEYDOWN/WM_SYSKEYDOWN/WM_KEYUP/WM_SYSKEYUP`，维护一份虚拟键按下状态。
- 钩子回调忽略带 `LLKHF_INJECTED` 标记的注入事件，不注入、不拦截、不修改原键盘事件，始终调用 `CallNextHookEx`。
- 回调不执行日志、配置写入、HTTP 或 WebView2 操作；定时器仍以原子方式生成 14 位 `activeMask`，展示页继续读取现有 `/api/key-mapping-state`。
- 如果钩子安装失败，立即取消“启用”状态、清空高亮并在 C++ 日志与 Web 提示中说明失败原因。

## 配置迁移

- `[KeyMapping]` 增加 `LayoutVersion=2`。
- 无 `LayoutVersion=2` 的旧配置首次读取时，保留已绑定的非零键位，将旧版明确保存为 `Vk=0` 且标签为空的槽位恢复为对应默认键。
- 迁移完成后立即写入 `LayoutVersion=2`。此后用户手动清空的 `Vk=0` 必须保持为空，不再恢复默认。
- “恢复默认键位”仍只修改 `vk/label`，不覆盖颜色和透明度。

## 生命周期与异常

- 钩子安装、卸载必须在主窗口生命周期内完成，且卸载操作幂等。
- 程序失去焦点不再清空高亮；只有收到对应 `KEYUP`、用户关闭功能或钩子卸载时清空。
- 为防止钩子安装前已按住的键没有 `KEYDOWN`，安装成功后先清空所有键状态，从下一次完整按键开始响应。

## 验证

- 默认 14 键在 DNF、主 Web、C++ 窗口和 KEY 窗口分别位于前台时均能响应。
- 同时按下多键、长按、重复绑定和 `Ctrl/Alt` 均正确高亮，松开后立即消失。
- 关闭功能后不再响应，重启程序后不会安装重复钩子。
- 旧的全空配置迁移为默认 14 键；迁移后手动清空再重启仍为空。
- 无按键时 KEY 窗口只显示矩形边框，内部保持透明；悬浮后边框和窗口控件正常变亮。
- 运行前端语法检查、按键映射静态回归、击杀展示页回归、`git diff --check` 和 Release x64 构建。
