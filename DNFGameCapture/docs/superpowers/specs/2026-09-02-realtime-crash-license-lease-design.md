# 实时同步崩溃修复与五天授权租约设计

## 目标

修复实时同步期间高频 Web 状态广播与 OCR 数据写入并发造成的崩溃风险，并将月卡及以上授权改为成功联网验证后五天内复用加密租约。

## 崩溃修复

- 成功的 `realtime_heartbeat_result` 不改变可见状态，不触发完整 Web 状态广播。
- 失败心跳仍更新实时同步状态并广播，让界面及时显示停止或错误。
- 构建 Web 状态时，在 `m_dataMutex` 内复制比分、选手、小号、最近识别和当前比赛快照；锁外再组合云端状态并序列化。
- Web 只发送最近 100 条识别记录，C++ 内部复盘历史不裁剪。
- 安装进程级未处理异常过滤器，在程序目录的 `crash-dumps` 下生成带时间和进程号的 MiniDump，同时保留现有日志。转储只保留基本崩溃与线程信息，不扫描额外进程内存；写入失败时删除无效文件。
- 只有主 EXE 的未处理原生异常进入该过滤器且文件写入成功时才会生成 `.dmp`；正常退出、单纯未响应、强制结束进程和 WebView2 子进程崩溃不会由该处理器生成转储。

## 授权租约

- 月卡及以上定义为卡密时长至少 30 天，永久卡也符合。
- 云函数成功验证后，将卡密、机器码、卡片时长、实际到期时间、验证时间、最后使用时间和云端地址写入版本化租约。
- 租约通过当前 Windows 用户的 DPAPI 加密，以 `REG_BINARY` 保存到 `HKCU\\Software\\DNFCapture`，不写入 `config.ini` 或明文文件。
- 启动时先验证卡密本地签名，再验证租约中的卡密、机器码、时长、时间回拨和实际到期时间。
- 租约有效截止时间为 `min(验证时间 + 5 天, 卡密实际到期时间)`；永久卡只受五天窗口限制。
- 命中租约时，只使用租约中最近一次授权成功返回的服务器地址，不使用硬编码或手工地址。
- 使用租约地址连续 30 秒未连接成功时，本次运行最多向云函数提前刷新一次服务器地址。
- 地址刷新成功后先将新验证时间和地址写入 DPAPI 加密租约，落盘成功后才切换运行中地址并重连。
- 地址刷新超时、失败，或返回的地址/有效期无效时，保留当前授权、旧地址和五天租约，继续重连旧地址。
- 手动换卡始终联网；成功后替换租约，失败后恢复旧卡及其仍有效租约。
- 测试卡和不足 30 天的卡每次启动联网验证，不创建租约。

## 兼容与失败处理

- 首次升级没有租约，仍需成功联网一次。
- 租约损坏、不匹配、过期或时间回拨时不启用授权，转入正常云函数验证。
- 五天到期时若云函数不可用，本次授权保持未通过；不会使用过期服务器地址。
- 授权界面继续显示卡片的真实到期时间，不显示租约截止时间。

## 验证

- 纯 C++ 策略测试覆盖月卡边界、五天边界、永久卡、实际到期和时间回拨。
- 静态回归检查覆盖成功心跳跳过广播、Web 数据锁和 DPAPI 存储约束。
- 运行现有云端同步与授权门禁检查、前端语法检查、`git diff --check` 和 Release x64 构建。
