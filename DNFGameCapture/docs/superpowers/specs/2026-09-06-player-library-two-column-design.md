# 选手与游戏 ID 双栏管理界面设计

## 目标

在不改变比赛识别、战绩、`alias_db.ini` 格式或云端协议的前提下，将选手身份与游戏 ID 管理界面调整为双栏布局，并统一使用“别名”术语。

## 界面结构

- 左栏显示可搜索的选手名称列表。
- 当前选中的名称置顶并使用红色选中状态。
- 同一身份组内的每个名称都保留独立列表项，并显示 `同一选手 · N 个名称` 标记。
- 部分重叠但未确认的名称显示 `可能是同一选手`，不自动归组。
- 右栏显示当前名称和所属身份组：
  - `同一选手 · 共 N 个名称`。
  - 以标签列出全部关联名称，名称之间平级，不设置主选手。
  - 统一显示一份共享游戏 ID，并显示游戏 ID 数量。
- 游戏 ID 默认只显示摘要；点击“编辑游戏 ID”后才展开完整编辑列表。
- 操作按钮使用：`添加别名`、`移出身份组`、`拆散身份组`、`编辑游戏 ID`。
- 删除别名前必须确认；删除只修改本地身份组与 `alias_db.ini`，不修改比赛快照、战绩或云端数据。

## 数据边界

- 身份组仍由 `player_identity_groups.json` 保存，旧 `alias_db.ini` 保持兼容。
- 归并、移出、拆散和别名删除继续调用现有 C++ 主线程命令。
- 云端仍只接收名称到游戏 ID 列表，不上传身份组字段。
- 选手在比赛中的识别名称保持原样，不因身份组归并而改名。

## 启动与进度体验

- 主页面先展示基础框架和选手/游戏 ID数量摘要。
- 选手库和身份组详情按需渲染，避免启动时一次性生成全部长列表。
- 底部进度区域无任务时隐藏；同步、推送或拉取开始时展开。
- 任务完成后保留 10 秒，然后自动收起，不改变主窗口布局。

## 性能结论

已通过启动计时确认：读取 `alias_db.ini`、身份组和选手列表通常在 0 至 16ms 内完成，完整 Web 状态构建约 400ms。启动白屏的主要耗时来自 WebView2 控制器首次冷启动，约 15 秒，不是选手或游戏 ID数量导致。

后续优化重点是 WebView2 初始化与首屏导航：先创建可见页面，再异步发送完整状态；数据详情按需展开。

## 验收标准

- 页面中不再使用“绰号”作为功能名称，统一显示“别名”。
- 选中名称置顶并标红，右侧能看到完整身份组和共享游戏 ID。
- 未点击编辑时不会渲染完整游戏 ID 编辑器。
- 同一选手提示和可能匹配提示不会撑高整个页面，列表区域可滚动。
- 无任务时底部进度区域不占布局空间。
- 原有身份组命令、云端 payload 和比赛数据行为不变。
