# 局域网手动比赛状态同步设计

## 目标

客户端连接按键局域网服务器后，允许用户手动从服务器获取一份比赛状态快照。快照包含队伍、比分和 8 个位置的战绩；客户端先展示差异，用户确认后才覆盖本地状态。普通按键心跳、重连和服务器连接建立都不能触发同步。

## 交互设计

- 服务器端只负责提供当前快照，不增加自动推送或自动覆盖逻辑。
- 客户端按键映射面板的“客户端”区域增加“获取服务器比赛状态”按钮。
- 点击后按钮进入“获取中...”状态；服务器返回后显示本地与服务器的差异，包括红蓝比分、选手主号/小号和击杀/死亡/AK。
- 用户点击“确认覆盖本地”后才应用；点击“取消”或连接中断都不修改本地。
- 应用前在内存中保留一份客户端旧比赛状态，并显示“撤销本次同步”。撤销只在本次程序运行期间有效。
- 同步失败、配对未完成、服务器忙或快照格式不合法时，只显示错误提示，不清空或修改客户端数据。

## 同步范围

快照字段：

- `redScore`、`blueScore`
- 8 个位置的 `team`、`name`、`aliases`
- 每个位置的 `kills`、`deaths`、`akCount`、`currentStreak`
- `redPickMode`、`isFlipped`
- `outputSeatLabelToKillFile`

明确不包含：

- 授权码和授权状态
- OCR 历史、最近识别和最近事件
- 按键绑定、按键高亮状态、局域网配对信息
- 主 Web 或击杀展示页的字体、颜色、布局配置

## 协议与线程边界

在现有 TCP 按键协议上增加独立消息类型，不把比赛状态塞进 `state` 心跳：

1. 客户端手动请求时发送 `team_sync_request`，携带递增 `requestId`。
2. 服务器收到后调用快照提供器，返回 `team_sync_snapshot`，携带相同 `requestId` 和快照对象。
3. 服务器无快照或构建失败时返回 `team_sync_error`。
4. 服务线程只负责网络收发；收到客户端快照后通过 Windows 消息投递到主线程，再由主线程解析和应用。
5. C++ 应用快照时复用现有 `m_dataMutex`、配置保存、TXT 输出、Web 广播和界面刷新流程。

快照版本固定为 `1`，必须是 8 个位置的数组；数值字段限制为非负整数，文本去除换行并限制长度，非法快照直接拒绝。一次只允许一个待处理请求，连接断开时自动失效。

## 兼容性

- 旧客户端和旧服务器仍可正常进行按键位置同步，只是不支持比赛状态同步。
- 新客户端连接旧服务器时，手动同步提示“对方版本不支持比赛状态同步”。
- 新服务器连接旧客户端时不会主动发送任何同步消息。
- 不改变现有 `[KeyMappingLan]` 配置结构；撤销备份不写入配置文件。

## 验收标准

- 普通连接、重连、按键状态心跳不会改变队伍、比分或战绩。
- 客户端点击获取后能看到差异，未确认前本地数据保持不变。
- 确认后比分、8 人主号/小号、击杀、死亡、AK、选人顺序和翻转状态一致。
- 应用后撤销可以恢复客户端应用前的全部上述字段。
- 断线、版本不支持、非法快照和服务器忙均不修改客户端数据。
