# 客户端封号、启动顺序与实时同步只读设计

## 目标

1. 主播后台将“强制断开”和“OCR 管控”统一为“封号/解封”，支持 1 天、1 周、1 个月、1 年、永久和自定义截止时间。
2. 封禁整台客户端：授权激活、授权会话、云端 Socket 和 OCR 均不可继续使用；封号后立即断开，过期或解封后恢复。
3. 软件启动时先显示击杀展示窗口，确认其页面已加载后再显示主 Web 窗口；异常时用有限超时放行主窗口。
4. 实时同步期间将八名选手、比分、击杀、死亡、重置、清空、交换、历史回溯等本地比赛编辑入口统一设为只读，并保留停止实时同步入口。

## 服务端设计

新增独立 `client_bans` 表，一条记录同时保存主播 Socket 设备号和授权机器号，避免只封住其中一条链路。服务端提供统一查询函数，授权激活、授权校验、受保护 API 与 Socket 握手都返回 `account_banned`。封号接口由服务端按预设时长计算截止时间，自定义时间必须晚于当前时间；永久封号使用空截止时间表示。执行封号时删除对应授权会话、停止实时同步关系并断开当前 Socket；解封删除同组封禁记录。

后台只对当前选中的主播操作，不再要求手填设备号或 Unix 秒。详情区显示封禁状态、时长选择和自定义时间输入；封号与解封都刷新列表状态。

## 客户端设计

Socket 收到 `account_banned` 后立即清除加密授权租约和服务器会话，关闭云端连接并停止本地 OCR，防止五天离线租约继续放行。重新启动后必须在线授权，因此封禁仍由服务端生效。

击杀窗口在主 Web 窗口之前创建并显示。击杀 WebView 导航完成后向主窗口发送就绪消息，主窗口稍作绘制延迟后显示；HTTP 或 WebView 初始化失败时最多等待固定时间，避免主界面永久不可见。

实时同步只读状态由 `cloudMatch.realtimeFollowing` 驱动。Web 根节点显示红色禁止提示，“运行”按钮显示“实时同步中”并禁用；比赛编辑控件统一禁用，历史快捷键和直接回溯也停止发送命令。原生层保留命令拦截并同步禁用专业模式里的比赛编辑控件，形成双层保护。

## 验证

- 服务端测试覆盖定时/永久封号、过期恢复、解封、双设备号关联、会话失效和 Socket 拒绝。
- 静态契约测试覆盖击杀窗口先显示、就绪/超时放行，以及实时同步只读控件与停止同步例外。
- 运行服务器完整测试、前端契约测试和 Release 构建。
