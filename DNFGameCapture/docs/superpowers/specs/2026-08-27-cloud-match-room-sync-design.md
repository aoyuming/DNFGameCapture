# 公网比赛房间与手动数据同步设计

## 目标

当某位主播掉线或本机识别中断时，仍能查看同一比赛房间内其他主播各自保存的比赛状态，比较哪些数据更可信，并由用户手动选择一名主播的快照覆盖本机。

本阶段只实现公网比赛房间同步。现有授权、共享小号库和自动更新逻辑保持不变。

## 用户流程

### 首次启动

软件没有保存房间身份时，启动后显示房间选择窗口：

- 李永房
- 温柔房
- 59房
- 不加入房间

选择房间后必须输入用于识别设备的主播名称。加入成功后保存服务器地址、房间 ID、主播名称、本机设备 ID 和设备令牌；下次启动自动恢复身份并连接，不再询问。

选择“不加入房间”只对本次启动有效，不写入“以后不询问”的状态，下次启动继续询问。

### 中途修改

“更多 > 云端比赛同步”提供：

- 当前房间、主播名称和连接状态。
- 修改主播名称。
- 切换到其他预设房间。
- 退出当前房间。
- 查看房间内所有主播的数据对比。

改名不改变设备身份。切换房间后，新房间只看到切换后的快照，不复制旧房间数据。

### 快照上传

客户端的比赛状态发生实际变化时，等待 400ms 合并连续修改，然后上传一份完整快照。输入名字等连续操作只上传合并后的最新状态。

上传不阻塞 UI、OCR、捕获或本地 TXT 输出。断网时本地功能继续运行；重连后上传当前最新快照，不补发中间的每一次变化。

每份快照包含：

- 红蓝比分。
- 8 名选手主号和小号。
- 击杀、死亡、AK 和连杀进度。
- 先后手、红蓝翻转、TXT 选人顺序开关和上一击杀队伍。
- 客户端递增 revision、客户端时间、服务器接收时间。
- changeSource：OCR、手动修改、本地恢复或云端同步。
- syncedFrom：如果当前状态来自其他主播，记录来源设备及来源 revision。

服务端只保存每台设备的最新有效快照，另保留有限审计记录用于排查连接和覆盖问题，不把审计记录用于客户端同步选择。

## 手动同步与比较

房间对比页按主播显示：

- 在线、离线和最后更新时间。
- 比分、名单、击杀、死亡、AK 和先后手摘要。
- 与房间多数派的相似度。
- 与本机的具体差异数量。
- 数据来源标记：本机识别、手动修改或从其他主播同步。

名单比较不能只按红蓝位置。服务端先用主号和小号集合匹配选手身份，再比较队伍归属和战绩；同时尝试正常视角与红蓝互换视角，选择身份匹配度更高的方向，避免不同主播左右视角相反造成误判。

相似度用于提示，不自动决定权威数据。计算权重为：

- 名单身份一致度 40%。
- 8 人战绩一致度 35%。
- 比分一致度 15%。
- 先后手、翻转和上一击杀队伍等比赛状态 10%。

更新时间超过 30 秒的数据标记为“可能过期”，超过 2 分钟的数据不参与多数派和相似分组，但仍可手动查看。

由云端同步复制出来、且之后没有产生新 OCR 或手动修改的快照，不作为独立一致票，避免一份数据被多人复制后形成虚假多数派。

用户点击某位主播后，先显示本机与目标快照的差异，再点击“同步到本机”确认覆盖。应用过程在 C++ 主线程完成完整校验和原子替换，随后保存配置、更新 TXT、专业窗口和 Web。

云端永远不能主动覆盖本机。手动同步前保存一份本地备份，允许撤销最近一次云端同步；新的本地比赛修改发生后，撤销入口失效。

## 服务端架构

新增独立服务目录，技术栈固定为：

- Node.js
- TypeScript
- Express
- Socket.IO
- SQLite

Express 提供健康检查和必要的身份/房间 REST 接口；Socket.IO 承担连接状态、加入房间、快照上传、房间摘要和手动获取目标快照。

服务端采用模块化单体结构：

- `identity`：设备注册、设备令牌和主播名称。
- `rooms`：预设房间、成员关系和在线状态。
- `snapshots`：快照校验、revision 去重和 SQLite 持久化。
- `comparison`：身份匹配、视角归一化、差异和相似度。
- `socket`：连接鉴权、房间事件和重连恢复。

SQLite 启用 WAL、外键和事务。数据库启动迁移中以稳定 ID 预置三个房间：`li-yong`、`wen-rou`、`59`，显示名称可独立保存，避免以后改显示名称破坏客户端配置。

## 身份与连接

客户端首次加入时生成随机设备 ID。服务端注册成功后返回不可预测的设备令牌，后续 Socket.IO 连接使用设备 ID 和令牌鉴权。主播名称只是房间内的显示标签，不作为安全身份。

同一房间内主播名称不要求唯一；界面在同名时附加设备 ID 后四位帮助区分。设备令牌只保存到本机配置，不进入日志、Web 状态或快照内容。

服务器地址作为客户端可配置项保存，本地开发默认连接 `http://127.0.0.1:18880`。正式部署支持替换为 HTTPS 地址，不在客户端写死域名。

## 数据边界与校验

- 快照采用版本化 JSON schema，第一版为 `schemaVersion: 1`。
- 单份快照最大 64KB，字符串长度、8 人数量和数值范围均在服务端校验。
- 客户端 revision 必须递增；旧 revision 和重复内容直接忽略。
- 服务端时间是在线状态和过期判断的唯一时间基准。
- 一个设备同一时间只保留一个有效 Socket 连接，新连接替换旧连接。
- 客户端收到目标快照后仍需执行相同 schema 和范围校验，不能直接信任服务器内容。

## 错误处理

- 服务器不可达：显示离线状态，本地识别不受影响，后台按退避策略重连。
- 身份失效：停止上传并提示重新加入，不删除本地比赛数据。
- 房间不存在：回到房间选择，但不自动选择其他房间。
- 快照无效或超限：服务端拒绝并记录原因，其他成员不受影响。
- 同步目标离线：允许读取其最后一份快照，并明显显示更新时间和过期状态。
- 手动应用失败：保持本机原数据，显示失败原因，不留下半应用状态。

## 客户端边界

新增公网同步服务类，网络线程和 C++ 主界面通过消息传递，不允许 Socket 回调直接修改比赛数据或 MFC 控件。

公网比赛同步与现有 `KeyMappingLanService` 相互独立：

- 局域网同步继续服务同一局域网的低延迟按键和比赛同步。
- 公网房间同步只保存多主播快照、提供比较和手动覆盖。
- 两者可以同时配置，但远端快照落地时统一走同一个比赛状态校验与应用入口。

## 测试

- 首次启动、选择不加入、加入三个预设房间及重启恢复。
- 修改主播名、切换房间和退出房间。
- 8 个模拟客户端连续上传、断线重连和 revision 去重。
- 名字连续输入时只上传合并后的最新快照。
- 正常视角与红蓝互换视角下的身份匹配和差异计算。
- 过期快照、复制来源去重、相似分组和多数派计算。
- 手动预览差异、确认覆盖、一次撤销和本地修改后撤销失效。
- 无效令牌、错误 schema、超过 64KB、异常数值和断网恢复。
- 公网服务不可用时，OCR、捕获、TXT 和局域网功能不受影响。
- Node 单元/集成测试、C++ 静态检查、前端语法检查、Release x64 构建。

## 非目标

- 不迁移现有授权、共享小号库或更新服务。
- 不自动选择“最正确”的主播。
- 不自动把云端状态覆盖到本机。
- 不同步 OCR 图片、最近识别截图、授权信息、按键配置或外观设置。
- 不提供公网按键状态转发。
