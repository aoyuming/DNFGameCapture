# 5.5.7 · 匹配按红蓝队伍收窄

## 变更

- **OCR 匹配按队伍收窄**：大 X 出现在哪一侧，死者就锁定在该物理侧所属的队伍里匹配，杀手只在对面的队伍里找。此前两侧都在上场 8 人里自由匹配，同队 ID 相近时会互相抢分。
- 物理侧与队伍的对应关系固定为：左侧 = 红队（`team 0`，索引 0-3），右侧 = 蓝队（`team 1`，索引 4-7）。该映射在项目里是硬约定（`m_players[i].team = (i < 4 ? 0 : 1)`）。
- `翻转红蓝` 只改变界面、网页和 OBS 输出的左右显示，**不改变**物理侧、OCR 区域、X 检测位置和候选队伍。
- 收窄覆盖全部匹配层：首轮精确别名命中、首轮模糊评分收集、两轮规则兜底、二轮降级、固定红框时间窗融合。
- **安全回退**：目标队伍 4 个座位没有填满时，该侧自动回退到上场 8 人，不会因为缺人而漏识别。回退与收窄都会写日志。
- **修正 `TeamToPanelSide` 映射方向**：原实现把 `team == 1` 映射到左框，与项目约定相反。后果是击杀确认后 `NotifyKillConfirmed` 清掉的是**杀手侧**的身份缓存，而设计意图是「只切死者侧，杀手侧保留」。已改为 `team 0 → 左框`。
- 应用版本 5.5.7；EXE FileVersion / ProductVersion 为 5.5.7.0，安装器 `AppVersion` 与前端缓存标识 `20261104-5.5.7-1` 同步。

## 未改变

- 所有匹配阈值不变：动态及格线（55/45/35/30）、首轮分差要求、短 ID 保护、职业硬隔离、融合层 `AcceptCandidate` 各分支条件。
- 「杀手与死者同队则拒绝落账」的检查保留，作为收窄之后的双保险。
- 单帧锁定策略、首轮统一决策、两轮兜底顺序均未调整。

## 日志

新增诊断行，排查识别问题时按标签抓：

```
[队伍收窄] 物理死亡侧=左(队伍0/红队=0) 物理杀手侧=右(队伍1)；
           死者候选范围=本队 4 人（已收窄）；杀手候选范围=对面队伍 4 人（已收窄）；
           说明=大X出现在哪一侧，死者就属于该侧队伍，杀手只在对面队伍里找；翻转红蓝不影响本规则。
[融合匹配][左框] 队伍收窄：目标队伍=0，候选 8 -> 4
```

名单不完整时对应位置显示 `上场 8 人（本队名单不完整，回退）`。
