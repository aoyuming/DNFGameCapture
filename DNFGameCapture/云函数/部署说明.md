# 云函数部署说明

## 推荐方式：Node.js 18 普通 HTTP 函数

上传项目生成的完整压缩包：

`deployment-packages/dnf-cloud-function-20260904.zip`

压缩包根目录必须直接包含：

- `index.js`
- `alias_append.js`
- `package.json`
- `package-lock.json`
- `node_modules/`

运行时选择 **Node.js 18**，函数入口填写：

`index.handler`

HTTP 触发器或函数 URL 需要允许客户端访问。授权函数的地址必须仍然是客户端内置的：

`https://verifykey-thaovfpoib.cn-hangzhou.fcapp.run/`

如果新函数生成了其他 URL，旧客户端不会自动知道新地址，需要让新函数沿用原 URL，或重新构建客户端修改入口地址。

## 环境变量

必须配置以下环境变量，不要写进 JS 或公开截图：

- `ALIBABA_CLOUD_ACCESS_KEY_ID`
- `ALIBABA_CLOUD_ACCESS_KEY_SECRET`
- `ALIBABA_CLOUD_SECURITY_TOKEN`（使用 STS 临时凭证时填写）

对应凭证需要能访问 OSS Bucket `dnf-capture-update`，区域为 `oss-cn-beijing`，至少需要读取、写入和删除本项目使用的对象。

## 测试顺序

1. 打开函数 URL 的 GET 请求，应返回 `{"ok":true}`。
2. 再使用控制台的测试功能或客户端验证真实卡密。
3. 在实时日志中确认没有 `Cannot find module`、`环境变量为空` 或端口启动错误。

## 截图中的自定义运行时

截图显示的是 **自定义运行时（Debian10）**。这种运行时不是普通 Node.js 18 函数，不能只上传两个 JS 文件；它还需要可执行的 `bootstrap` 启动文件。最简单的做法是改用上面的 Node.js 18 普通 HTTP 函数并填写 `index.handler`，不要把本项目按自定义运行时部署。

`alias_append.js` 只是 `index.js` 使用的辅助模块，不是第二个云函数。
