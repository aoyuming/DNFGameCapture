# 测试服密钥管理更新

仅更新测试服 `28880 / 28881`，不需要重新部署云函数、OSS或更新客户端。此包也包含此前的共用ID和5/3自动归并修复，不修改正式服。

## 功能

- 卡种下拉选择：1小时、1天、7天、10天、3个月（90天）、半年（180天）、1年（365天）、永久。
- 新卡首次激活开始计时。支持一次生成1至200张，单张复制、整批复制和导出TXT。
- 密钥列表可查看完整卡密。新卡加密保存；旧记录若只有哈希不能反推原文，可补录匹配的卡密，或在该卡下次成功激活/卡密验证时自动补存。
- 增加时长：未到期从原到期时间增加，已过期从现在增加；未激活卡增加待激活时长。可转永久，永久卡加有限时长仍为永久。
- 换绑：选择曾成功验证过的授权机器码，或解除绑定后由下一台设备激活。授权机器码和主播连接ID不是同一种编号，不能互换。换绑不重置原激活时间和到期时间。
- 操作有确认和日志，重试不会重复生成或重复加时。旧卡的原到期时间、禁用状态和绑定保持不变。

## 更新步骤

把压缩包解压到新目录，在解压出来的 `dnf-cloud-match-server` 目录执行。先停止并备份测试服的整个数据目录、旧程序和配置：

```bash
sudo systemctl stop dnf-cloud-match-test
backup="/root/dnf-test-before-license-$(date +%Y%m%d-%H%M%S)"
sudo mkdir -p "$backup"
sudo cp -a /var/lib/dnf-cloud-match-test "$backup/data"
sudo cp -a /opt/dnf-cloud-match-server-test "$backup/app"
sudo cp -a /etc/default/dnf-cloud-match-test "$backup/environment"
echo "$backup"
sudo bash deploy/install-test.sh
curl -fsS http://127.0.0.1:28880/health
curl -fsS http://127.0.0.1:28881/admin/health
sudo journalctl -u dnf-cloud-match-test -n 40 --no-pager
```

后台地址：`http://47.109.149.111:28881/admin/licenses`。原管理员密码不变。

## 重要备份说明

首次保存完整卡密时会在数据库旁自动生成 `cloud-match-test.sqlite.license-key`，Linux权限为0600。它是随机生成的卡密加密文件，不是管理员登录密码。

**数据库和 `.license-key` 必须一起备份和迁移。不要删除这个文件，也不要把测试服的文件覆盖到正式服。** 修改管理员密码不影响卡密解密。如果加密文件丢失，原来的授权哈希仍可验证，但已加密卡密无法查看；应恢复原文件，不要创建一个新文件冒充旧文件。

这次更新包含数据库迁移。回退时应停止测试服并成套恢复旧程序、完整数据目录和原配置，不能只替换旧版JS。

## 使用边界

- 换绑或禁用会撤销服务器授权会话；下一次授权接口或共享库请求会被拒绝。现有主播连接采用另一套设备身份，这不是一键踢出主播操作。已经发放的客户端离线授权租约无法远程立即删除，长期卡旧设备的本地功能可能仍可用至租约到期。
- 加时后的客户端到期显示以重新联网验证返回的时间为准；服务器不会修改用户电脑里的旧离线缓存。
- 当前沿用HTTP管理入口，不具备传输加密。建议用SSH隧道访问或将安全组28881限制为自己的IP，不要公开分享后台密码或导出的卡密TXT。
- 自动记录只含操作和授权元数据，不把卡密或会话令牌写进操作日志。
