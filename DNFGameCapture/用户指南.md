# DNF 自动人头记分用户指南

这份指南面向实际比赛使用者，按“准备、授权、填选手、校准死亡 X、开始监控、接入 OBS”的顺序说明。

## 1. 使用前准备

请先确认这些条件：

- Windows 电脑。
- 已安装 Microsoft Edge WebView2 Runtime。
- 软件同目录有 Umi-OCR，或能手动启动 `Umi-OCR.exe`。
- 有可用的授权 CDK。
- 如果使用“打补丁红蓝判断”死亡 X 算法，EXE 同目录需要有 `sprite(击杀大XX).NPK`。

建议先关闭游戏再安装死亡 X 补丁；如果游戏已经运行，复制补丁后也需要重新上游戏才会生效。

## 2. 首次启动

1. 启动 `DNFGameCapture.exe`。
2. 在 Web 记分窗口点击 `授权`，输入 CDK。
3. 授权正常后，选择要捕获的目标：
   - 默认会寻找 `地下城与勇士：创新世纪` 窗口。
   - 也可以从目标下拉框选择指定窗口、摄像头或采集卡。
4. 选择捕获引擎：
   - `自动选择`：推荐，优先 WGC，失败后走兼容模式。
   - `WGC 硬件捕获`：画面更稳，适合支持的系统。
   - `PrintWindow`：WGC 异常时使用。
5. 点击底部输出目录栏，可更改 TXT 输出目录。

授权 CDK 会同时保存在 EXE 同目录的 `license.txt` 和当前 Windows 用户注册表里。程序启动时优先读取注册表，并会自动互补缺失的一方：如果蓝屏或异常断电导致 `license.txt` 变空，会用注册表里的授权码自动恢复；如果注册表缺失，会用 `license.txt` 自动补回。

## 3. 填写选手和小号

界面分为红队和蓝队，每队 4 个位置。每个选手都要填写主号，并至少绑定一个小号。

小号规则：

- 主号主要用于显示和归属，不直接参与 OCR 名称匹配。
- 上场选手没有小号时，不能开始监控。
- 真实 ID 少于 3 个字符时，需要补充大区或职业，否则容易误识别。
- 推荐小号格式：
  - `真实ID`
  - `大区真实ID`
  - `真实ID#职业`

在选手输入框旁打开小号菜单后，可以：

- `绑定新小号`：给当前主号添加小号。
- 修改小号：同步修改永久小号库。
- 临时解绑：只在本次场上隐藏，不从底层库删除。
- 永久解绑：从小号库彻底删除。

## 4. 云端小号库

- `同步云端库`：从公共小号库拉取数据并合并到本地，不会删除本地已有小号。
- `推送本地库`：把本地小号库变化提交到云端待审核区。
- 管理员可使用隐藏直写模式直接写公共库；普通用户不需要使用。

如果刚同步过云端库，程序会记录一份基线，用来判断之后本地库有哪些新增或删除。

## 5. 死亡 X 算法和 X 校准

死亡 X 是判断选手是否死亡的关键点位。软件目前有两种算法：

- `大X颜色个数判断`：不需要补丁，按死亡 X 的红橙颜色和斜线采样点判断。
- `打补丁红蓝判断`：需要安装 `sprite(击杀大XX).NPK`，按补丁后的红蓝采样点判断。

在 C++ 专业窗口预览画面里，会常驻显示当前选中算法实际检测的点位：

- 选择 `大X颜色个数判断` 时，会显示每个死亡 X 周围的斜线采样点。灰色空心点表示本帧未命中，亮色实心点表示命中。
- 选择 `打补丁红蓝判断` 时，会显示每个死亡 X 的上、下、左、右 4 个采样点。红/蓝点表示识别到补丁颜色，灰白点表示当前点未合格。
- 下方左右放大框也会同步显示这些点，方便细看是否对准。

如果检测点因为窗口尺寸、标题栏裁剪、采集方式或视频源比例偏移而不准，可以手动校准：

1. 打开 C++ 专业窗口。
2. 点击顶部 `X校准`。
3. 在预览画面上拖动 8 个标记，顺序是：`左主、左1、左2、左3、右主、右1、右2、右3`。
4. 拖动时，实际判定坐标和预览检测点会实时跟着移动。
5. 鼠标不方便时，可以按数字键 `1` 到 `8` 选择点位；方向键每次移动 1 个预览像素，`Shift + 方向键` 每次移动 10 个预览像素。
6. 点击 `保存X点位` 后写入 `config.ini`，下次启动继续生效。
7. 点击 `取消` 会恢复进入校准前的点位。
8. 点击 `恢复默认` 会回到软件内置默认点位；如果想长期使用默认点位，需要再点击 `保存X点位`。

点位保存到 `config.ini` 的 `[Settings]` 下，使用归一化比例坐标，所以同一捕获画面尺寸下会自动按比例适配。更换捕获方式、裁剪标题栏或视频源比例后，建议重新检查一次 X 点位。

## 6. 开始比赛监控

1. 确认红蓝队选手和小号都填写完整。
2. 确认 Umi-OCR 已启动；如果没启动，程序会尝试自动拉起。
3. 选择死亡 X 算法。
4. 如有必要，在专业窗口用 `X校准` 调整死亡 X 点位。
5. 点击 `运行` 开始监控。
6. 再次点击可停止监控。

监控中程序会自动识别击杀、死亡、AK 和总比分，并刷新 Web 界面与 TXT 文件。

## 7. 常用操作

- `翻转红蓝`：交换左右显示和输出方向，适合 OBS 画面左右队伍与软件相反的情况。
- `最近识别`：查看本轮自动识别记录，可撤销或恢复某条识别战绩；点击 `重置战绩` 会清空最近识别记录。
- `C++日志`：查看底层识别、同步和错误提示。
- `清空红队` / `清空蓝队`：清空对应队伍选手。
- `重置战绩`：清空击杀、死亡、AK、总比分和最近识别记录。
- 选手行可拖动/交换，方便调整位置。

## 8. OBS 接入

在 OBS 中添加文本源，读取输出目录里的文件：

- `比分.txt`：总比分，例如 `3-2`。
- `左侧人头.txt`：左侧队伍每名选手的击杀/死亡/AK。
- `右侧人头.txt`：右侧队伍每名选手的击杀/死亡/AK。
- `击杀.txt`：左右两边的击杀简表。

如果使用了 `翻转红蓝`，这些输出会跟随翻转后的左右方向。

## 9. Web 记分窗口显示

Web 记分窗口会自动适配不同分辨率、Windows 缩放和 WebView2 的实际缩放。正常情况下，各种分辨率和 100% / 125% / 150% 缩放下都应保持同一套紧凑布局比例；如果某台电脑存在额外 DPI 或兼容性缩放，程序会根据前端实测视口自动校正 WebView 缩放。

如果远程电脑出现窗口裁切、比例异常或底部内容看不到：

- 先确认对方运行的是最新 `DNFGameCapture.exe`，并且 EXE 同目录的 `web前端` 文件夹也一起更新。
- 打开一次 Web 记分窗口后，让对方发送 `match_debug.log` 里包含 `[Web布局诊断]` 的几行。
- 正常日志一般会看到 `layoutVersion=20260515-layout-fit-diagnostics`，并且校正后 `inner` 接近 `720x560`、`fitScale=1.000`。
- 如果日志出现 `自动校正WebViewZoom`，说明该电脑有额外缩放，程序已自动修正；随后 `原因=zoom-calibrated` 的诊断行应显示恢复后的尺寸。

## 10. 常见问题

### 授权失败或过期

重新点击 `授权` 输入 CDK。CDK 会和当前机器绑定，如果提示已绑定其他机器，需要联系管理员处理。

如果遇到蓝屏、断电后 `license.txt` 变空，正常重新启动软件即可自动从注册表恢复。C++ 日志里的授权状态会显示本地卡密来源和是否执行了自动补写。

### Umi-OCR 未运行

程序会尝试自动启动。若仍失败，请手动打开软件同目录下的 `Umi-OCR.exe`，等待 OCR 服务启动完成后再点 `运行`。

### 检测不到游戏窗口

确认 DNF 窗口标题包含 `地下城与勇士：创新世纪`，或在目标下拉框里手动选择正确窗口。也可以选择摄像头或采集卡作为输入源。

### WGC 捕获失败

把捕获引擎改为 `自动选择` 或 `PrintWindow`。WGC 依赖系统和窗口状态，失败时兼容模式更稳。

### 打补丁红蓝判断无法启用

确认 EXE 同目录有 `sprite(击杀大XX).NPK`。程序会尝试找到 DNF 的 `ImagePacks2` 目录并复制补丁；找不到时，可以在 `config.ini` 的 `[Settings]` 下写入 `ImagePacks2Path`。

### 死亡 X 点位不准

先确认捕获画面是否包含标题栏、边框或黑边。如果死亡 X 标记和实际游戏 HUD 有偏移，进入 C++ 专业窗口点击 `X校准`，拖动 8 个点到实际死亡 X 位置。预览画面上显示的采样点就是当前算法实际检查的位置。

### 切换算法后点位显示不一样

这是正常的。`大X颜色个数判断` 看斜线上的多个颜色采样点；`打补丁红蓝判断` 只看上、下、左、右 4 个补丁颜色点。当前选择哪种算法，预览就显示哪种算法的检测点。

### 开始监控提示选手信息不完整

检查每个上场选手是否至少有一个小号。2 字短 ID 还需要补充大区或 `#职业`，例如 `某ID#剑魂`。

### 云端库同步和推送有什么区别

`同步云端库` 是从公共库拉取并合并。`推送本地库` 是把本地变化提交到云端待审核，不会立刻变成公共库，除非管理员审核通过或使用管理员直写。
